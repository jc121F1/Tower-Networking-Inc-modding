# Power over Ethernet

A LuaJIT mod for Tower Networking Inc 0.12.0+. Enable it alongside `luajit-support`.

While a powered switch is connected to a device over Ethernet, the mod temporarily moves the endpoint's `Power` loads to the switch's `PowerController` using the game's `remove_local` and `add_local` methods, then updates each `Power.controller` back-reference. This includes the main logic load and auxiliary loads used by components such as status lights. In game 0.12.7, `add_local` alone adds a load to the new controller's `locals` but leaves the back-reference on the original controller. The mod refreshes both controllers, calls `Power.on()`, and sends the exposed `Power.broadcast_restored()` event to normal power listeners. When Ethernet is removed, it returns each load to its original controller and sends `Power.broadcast_lost()` while retaining power intent. This avoids duplicating or changing physical power sockets.

The prototype uses a 120W per-switch budget and a 15W per-endpoint limit. It scans every 30 game ticks and logs electrical and OS state separately. Before transfer it estimates demand from the endpoint's live load, configured fallback load, logic-controller load, and original power-controller rate, rejecting unknown or over-limit loads. It also checks combined live load after auxiliary components start. The latest game log shows that the switch's own `power_controller` and its upstream controller are the same object in this setup; choosing between them did not change power delivery. Broadcasting restoration booted the EthTapper on initial load, and the revised disconnect path allowed reconnection. The game exposes separate `Power` objects on powered lights and switches, so the mod transfers those auxiliary loads as well. The game still renders "Unpowered" in the device hover despite a live PoE-powered `Power` object, so the mod corrects that hover label to green "Powered" while the endpoint has an active PoE link; it restores its prior text when power is lost. It connects to the hover label's `finished` signal so the correction can happen as soon as the game builds the hover text, with the 30-tick scan retained as fallback. The user confirmed that the signal correction appears on first hover. This display adjustment currently targets the English "Unpowered" label. Per-tick hover polling caused sandbox illegal-opcode faults, so it is not used. The earlier run exhausted the Lua sandbox heap after repeated scans, so the mod reuses each device's Ethernet socket list within a scan, logs only meaningful scan changes, and drains wrapper allocations at the end of each game tick using the pattern established by the wireless-access mod. The game also emits `untested codeflow: controller change on power object` when the mod updates `Power.controller`.

Set `AUDIT = true` near the top of `entry.lua` to enable detailed `diag` lines on each 30-tick scan. It defaults to `false` for normal play; scan summaries, transfers, and errors still log. Device lines show electrical and OS state, both controller IDs, supply and charge state, current load, PoE source, and auxiliary Power loads. Edge lines identify socket pairs and physical cables. Candidate lines show estimated watts and why a source was selected or rejected. A snapshot is capped at 128 devices, 256 edges, and 256 candidates; truncation is logged. The diagnostics identify switch-to-switch candidates and switches sharing a node name. Source selection uses instance IDs. These logs do not change power routing.

PoE-powered switches are terminal endpoints: they may run as network switches, but the mod will not use them as PoE sources. It also leaves already powered devices on their existing supply instead of moving their loads to a neighboring switch. PoE is supplied only when the endpoint's original power controller reports `disabled=false`, which tracks its power switch in the tested Blade5 and EthTapper. Switching either off removed its existing PoE link on the next scan; switching the Blade5 back on restored PoE. An endpoint with an active PoE link retains that source until the link is removed; another source can be selected on a subsequent scan. These rules prevent the reciprocal transfer observed between two mains-powered Blade10 switches and avoid accidental power cycles through downstream switches.
